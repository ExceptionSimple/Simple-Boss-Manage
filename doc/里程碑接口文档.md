# 里程碑接口文档

- 日期：2026-10-27
- 操作人：lovexiaoling

## 1. 通用约定

- 基础路径：`/api`
- 业务查询 / 写入接口要求查询参数 `milestone_id`（整数，必填）。
- 写接口与报告生成接口在里程碑不存在时返回 HTTP 404；纯查询接口在里程碑不存在时返回空数据。
- 对已保存（frozen）的里程碑执行写操作：HTTP 409，detail 为 `M{x} 已保存，只读不可修改`。
- 以下接口不要求 `milestone_id`：`/config`、`/cookie`、`/messenger/login`、`/messenger/check-login`、`/messenger/import-cookies`、`/messenger/generate-message`、`/reports/list`、`/reports/delete`、`/reports/view/{filename}`。

## 2. 里程碑

### GET /api/milestones

返回全部里程碑，按 ID 升序。

```json
{
  "items": [
    {
      "id": 1,
      "name": "M1",
      "status": "frozen",
      "created_at": "2026-10-20 09:00:00",
      "frozen_at": "2026-10-27 10:00:00",
      "boss_count": 32,
      "message_count": 480
    },
    {
      "id": 2,
      "name": "M2",
      "status": "active",
      "created_at": "2026-10-27 10:00:00",
      "frozen_at": null,
      "boss_count": 5,
      "message_count": 61
    }
  ]
}
```

### POST /api/milestones

创建下一个里程碑（名称自动取当前最大编号 + 1）。若存在 active 里程碑，先将其冻结。

响应：

```json
{ "id": 3, "name": "M3", "status": "active", "created_at": "..." }
```

### POST /api/milestones/{id}/save

保存（冻结）指定里程碑。

- 成功：`{ "ok": true, "milestone": { "id": 1, "name": "M1", "status": "frozen", "frozen_at": "..." } }`
- 里程碑不存在：404
- 里程碑已保存：409

## 3. 投递列表

### GET /api/bosses

查询参数：

| 参数 | 类型 | 说明 |
|------|------|------|
| milestone_id | int | 必填 |
| city / position / keyword | string | 筛选 |
| has_interview / is_resume_sent / has_written_test | int | 0/1 筛选 |
| sort_by / order / page / size | | 与原逻辑一致 |

只返回指定里程碑的 BOSS 和岗位信息。

### GET /api/bosses/{encrypt_boss_id}?milestone_id=

返回指定里程碑下的 BOSS 详情，找不到返回 404。

### PATCH /api/bosses/{encrypt_boss_id}?milestone_id=

更新面试 / 简历 / 笔试 / 投递日期。要求里程碑为 active，否则 409。

### DELETE /api/bosses?milestone_id=

清空指定里程碑的 BOSS 和聊天记录，不影响其他里程碑。要求 active，否则 409。

### GET /api/bosses/{encrypt_boss_id}/messages?milestone_id=&page=&size=

返回指定里程碑下的聊天记录。

## 4. 统计

以下接口均要求 `milestone_id`，只统计该里程碑的数据：

- `GET /api/stats/overview`
- `GET /api/stats/cities`
- `GET /api/stats/positions`
- `GET /api/stats/daily`
- `GET /api/stats/daily-resume`
- `GET /api/stats/recent-resumes`
- `GET /api/stats/sync-logs`

## 5. 消息提醒

以下接口要求 `milestone_id`：

| 接口 | 说明 | 写操作校验 |
|------|------|-----------|
| GET /api/reminders | 待提醒列表 | 否 |
| POST /api/reminders/preview | 生成预览 | 是，要求 active |
| POST /api/reminders/send | 发送提醒 | 是，要求 active |
| POST /api/reminders/send-messages | 发送指定消息 | 是，要求 active |
| GET /api/reminders/failed-queue | 失败队列 | 否 |
| POST /api/reminders/failed-queue/retry | 重试失败队列 | 是，要求 active |
| DELETE /api/reminders/failed-queue | 删除失败记录 | 是，要求 active |

失败队列只读取 / 操作指定里程碑的记录。

## 6. 消息发送

### POST /api/messenger/send?milestone_id=

发送单条消息。要求 active，否则 409。

### POST /api/messenger/send-batch?milestone_id=

批量发送。要求 active，否则 409。

发送失败时写入 `message_failed_queue`，并带上当前 milestone_id。

### POST /api/messenger/generate-message

只读取全局配置生成消息，不需要 `milestone_id`。

## 7. 同步

### POST /api/sync?milestone_id=

触发同步，SSE 流式返回。要求目标里程碑为 active，否则 409。
所有写入（bosses、job_info、chat_messages、sync_logs）都带该 milestone_id。

### GET /api/sync/logs?milestone_id=&limit=

返回指定里程碑的同步日志。

## 8. 报告

所有报告接口要求 `milestone_id`，按该里程碑的数据生成：

- `GET /api/reports/weekly`
- `GET /api/reports/weekly-current`
- `GET /api/reports/monthly`
- `GET /api/reports/monthly-current`
- `GET /api/reports/custom?start=&end=`

报告标题追加里程碑名称。报告文件仍保存在统一的 `reports/` 目录。

报告列表 / 删除 / 查看接口不区分里程碑：

- `GET /api/reports/list`
- `DELETE /api/reports/delete`
- `GET /api/reports/view/{filename}`

## 9. 配置

`GET /api/config`、`PUT /api/config`、Cookie 相关接口保持全局，不受里程碑影响。
